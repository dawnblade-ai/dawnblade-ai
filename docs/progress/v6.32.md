# Progress report — v6.32 (2026-11-14)

## What shipped
- **Ranked tables.** When you open a server table you can switch it from *Friendly* to *Ranked*. Both players need a signed-in phone and a player name; if not, the screen says
  what to do ("Choose yours under Playing as, then try again"). The lobby and the board show "Ranked" and each player's rating next to their name.
- **Ratings.** Everyone starts at 1200 (Elo, K 32, a draw is half a point). When a ranked game ends the server records the result once and moves both ratings. Your end screen says
  how your rating moved ("Your rating rose from 1300 → 1312 (+12)"). The name sheet shows your rating and your record.
- **Who goes first** is the same as at every server table: rock-paper-scissors, the winner chooses. Friendly tables are unchanged.

## Not known / not built yet (the honest list)
- **Not deployed.** One new SQL file (`006_ratings.sql`, run it first) and a new function version. The live check was written but has not run on the real project.
- **Closing a ranked table mid-game records nothing**, so a creator could close to dodge a loss. The forfeit clock (a later release) closes this. There is no leaderboard screen yet.
- A player who plays ranked on a throwaway sign-in and then recovers their old player with a recovery code loses that throwaway's rating (it is deleted with the player).
- Nothing stops two friends farming rating by conceding on turn one; a minimum-length rule is a question for the user.

## How it was proven
- See the CHANGELOG entry and `server/S5-LOG.md`: drills each with a sabotage that must fail, the SQL on PGlite (twice, 20 sabotages, the shared Elo table) and on a real Postgres 16 (two games of one player finishing at once),
  the function under Deno (a full ranked table to a recorded result), the page drive at 393x852.
