# Progress report — v6.30 (2026-11-14)

## What shipped
- **A lost phone is not a lost player.** On the name sheet (*Find an opponent* → *Join a server table* → *Choose a name*) there is now **Get a recovery code**
  and **I have a code**. The code is shown once: write it down. Getting a new one makes the old one stop working.
- **On a new phone,** type the code and the sheet says "Welcome back, <your name>". Sit down at your table and your seat is yours again. Your old phone
  keeps working too (one player, two phones; the last one to sit down holds the seat).
- A code works once. A wrong, used, expired or replaced code all get the same plain answer, so a guesser learns nothing. After eight wrong tries
  in an hour the phone is asked to wait.
- The codes are long enough (74 bits) that guessing is hopeless, and the server stores only a scrambled fingerprint of each one, never the code.

## Not known / not built yet (the honest list)
- **Not deployed yet.** The new SQL file and the new function version are waiting for the CEO; until then the buttons answer "the server is not answering".
- **The live check was written but has not run against the real project** (the new parts do not exist there yet). Everything else was run offline:
  the drills, the real page at phone size, the function under Deno, and the SQL on an offline Postgres.
- Anyone holding the code can become the player: treat it like a password. Lose the code and the phone and the player is still gone.
- A phone sitting at a table must leave it before it can recover a different player (so no seat is stranded).
- Not built yet: the cap of 5 open tables per player, ranked play, names on the board.
